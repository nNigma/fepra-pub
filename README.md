# training-journal — «Кузница»

Личный тренировочный сервис: **Telegram-бот [@kuznitsa_bot](https://t.me/kuznitsa_bot)
для ввода + Mini App для аналитики**. Основной спорт — кроссфит, плюс бег / вело
(биометрия с часов Garmin). Активный анализ для решений: нагрузка (ACWR/TRIMP),
готовность, прогрессия по уровням, разбор тренировки от ИИ.

> Архитектура и решения — в [`SPEC.md`](./SPEC.md).

## Что умеет

- **Запись тренировки в боте.** Фото доски WOD или текст → распознавание (Gemini
  vision + онтология движений) → авто-шаблон результатов по формату WOD → разбор:
  силовые максы уходят в уровни, метконы (время/круги/счёт) — в сводку.
- **Цели и уровни.** Каталог дисциплин (лифты + бенчмарки Girls/Hero) с нормативами
  по кратности веса тела (шкала Strength Level), общий уровень атлета, прогресс до
  следующего тира. Распознавание вариантов (рывок в сед/в стойку, взятие с пола/с
  виса) с уточнением в боте, если не однозначно.
- **Программа зала.** Общая доска дня для зала (Universe): добавляет админ, участники
  видят при записи; стандартизация упражнений через онтологию.
- **Соревнования.** Карточка старта, этапы, места, перцентили, радар способностей,
  динамика, «стоит в очках».
- **Лидерборд зала**, **самочувствие** (когда нет часов — готовность по самооценке).
- **Разбор от ИИ.** Быстрый разбор от Gemini по тапу + глубокий «🎩 Разбор от Месье
  Клода» (пишется скиллом). Тренерский текст: как подошёл, как прошла, разбор работы,
  совет. Плюс шуточный «🔮 Астро-разбор» по желанию.
- **Garmin.** Синхронизация своих часов и часов друзей (токен-only, MFA через бота).
- **Мультиюзер** (режим тренера: админ видит всех view-only), **локали RU/EN**.

## Стек и раскладка

Источник правды — **SQLite `training.db`** (не plaintext). Три пакета:

```
src/
├── tj/                     # ядро: анализ, онтология, нормативы, LLM-клиент, i18n
│   ├── analysis/           #   TRIMP/ACWR, уровни, сводка, соревнования, WOD-нотация,
│   │                       #   разбор результатов, narrative, лидерборд, gym-стата
│   ├── data/               #   standards.json (нормативы), benchmarks.json (WOD Girls/Hero)
│   ├── ontology.py         #   движения RU/EN → канон (+ маркеры вариантов)
│   ├── llm.py  i18n.py     #   клиент Gemini; каталог строк RU/EN
│   ├── models.py config.py #   каноническая схема; config.toml + .env
│   └── cli.py + adapters/ vault/ store/   # legacy Obsidian/Garmin-слой (см. ниже)
├── tjbot/                  # Telegram-бот (слой ВВОДА)
│   ├── db.py               #   training.db: схема, CRUD, сиды нормативов
│   ├── handlers/           #   онбординг, запись/правка тренировки, программа зала,
│   │                       #   соревнования, цели, самочувствие, профиль, admin, garmin
│   ├── vision.py           #   распознавание фото доски/результатов (Gemini)
│   └── garmin_sync.py garmin_connect.py   # per-user синк + MFA-мост
└── tjapp/                  # FastAPI Mini App (слой ОТЧЁТОВ)
    ├── api.py auth.py      #   REST + валидация Telegram initData
    └── static/             #   index.html, app.js, strings.js
```

**Разбор от Месье Клода** пишется отдельным скиллом `kuznitsa-claude-review`
(лежит вне репо, гоняется против серверной БД).

## Быстрый старт (локально)

Telegram открывает Mini App только по публичному HTTPS-URL. Локально его бесплатно
даёт временный тоннель **cloudflared** — лаунчер сам всё поднимает и подставляет URL.

```bash
cp .env.example .env    # заполни TG_KUZ_BOT_TOKEN, OWNER_TG_ID, GEMINI_API_KEY (подсказки внутри)
make setup              # venv (Python 3.12) + зависимости через uv
make run                # Mini App + тоннель + бот — одной командой
```

`make run` поднимает uvicorn, запускает cloudflared, кладёт свежий публичный URL в
`miniapp_url.txt` (бот читает его на лету) и стартует бота. Нужен установленный
`cloudflared` (macOS: `brew install cloudflared`). Тесты — `make test`.

## AI-движок: только Gemini (по умолчанию) или Claude

Из коробки бот работает **только на Gemini** — достаточно одного бесплатного
`GEMINI_API_KEY`. Все ИИ-функции (разбор тренировок, тренер, распознавание фото
доски/еды, глубокий «Разбор от Месье Клода») идут через Gemini.

Если у тебя есть Claude — включается одним флагом в `config.toml`:

```toml
[llm]
use_claude = true
```

Тогда пайплайн становится Claude-first с фолбэком на Gemini. Для `use_claude = true`
нужно **одно из двух**:
- установленный и залогиненный Claude Code CLI (`claude` в `PATH`, по подписке), **или**
- `ANTHROPIC_API_KEY` в `.env` (текстовые разборы через API; распознавание фото
  остаётся на Gemini).

Если нет ни того, ни другого — в лог уйдёт предупреждение, и всё мягко откатится
на Gemini, ничего не сломается.

## Прод (постоянный хостинг)

Сервер вне РФ (Gemini API не ходит с росс. IP): systemd-юниты `kuznitsa-bot` +
`kuznitsa-app`, реверс-прокси **Caddy** (Let's Encrypt HTTPS) на твоём домене
(например бесплатный `<your>.duckdns.org`) и постоянный `MINIAPP_URL`. Пошаговый гайд
и готовые шаблоны — [`deploy/README.md`](./deploy/README.md). Обновление — `git pull`
+ рестарт сервисов; данные (`training.db`, токены, `.env`) не трогаются.

## Legacy: Obsidian/CLI-слой

Проект начинался как plaintext-дневник в Obsidian с CLI `tj` (`seed`/`sync`/`build`/
`analyze`/`report`): часы Garmin → `raw/` → канон → md-заметки → БД-кэш. Этот слой
(`tj/cli.py`, `adapters/`, `vault/`, `store/`) сохранён и работает, но **источником
правды теперь является `training.db`**, а основной ввод — бот. CLI полезен для
бэкфилла истории Garmin и офлайн-анализа.
