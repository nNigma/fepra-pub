# PWA / API — контракт для всех, кто работает над выходом из Telegram

## Окружение
- Тесты: `make test` (или `PYTHONPATH=src .venv/bin/python -m pytest tests/ -p no:randomly -q`).
  Весь набор должен оставаться зелёным. Сеть и LLM в тестах не вызываем: мок.
- Python 3.12+, зависимости — `make setup` (extra `bot`: fastapi, httpx, python-multipart, webauthn, pywebpush,
  cryptography). Новую зависимость — в `pyproject.toml` (extra `bot`).
- Node 20+ / npm для фронта (`web/`).

## Правила
1. **Бот не переписываем.** `tjbot/handlers/*` не трогаем (кроме случаев, оговорённых в задаче). Бот живёт на той же БД
   как запасной клиент, поэтому схема меняется **только добавлением** (новые таблицы, новые nullable-колонки).
2. **Логика в сервисах.** Доменный код — `src/tj/services/<домен>.py` (чистые функции над sqlite-соединением, без HTTP,
   без Telegram). HTTP — `src/tjapp/routes/<домен>.py`: валидация, права, вызов сервиса. Существующую логику из
   `tjbot/db.py`, `tjbot/vision.py`, `tj/analysis/*` **переиспользуем**, а не копируем.
3. **Роутеры.** Каждый модуль роутов экспортирует `router = APIRouter()` и регистрируется одной строкой в списке
   `ALL_ROUTERS` в `src/tjapp/routes/__init__.py` (файл заводит Волна 1). `api.py` подключает `ALL_ROUTERS` циклом.
   Так параллельные ветки не конфликтуют в `api.py`.
4. **Миграции.** Пронумерованные модули `src/tj/migrations/NNNN_name.py` с функцией `upgrade(con)`; реестр и
   `schema_version` в `meta` заводит Волна 1. Диапазоны номеров: 0001–0019 фундамент/вход, 0020–0029 тренировки/
   загрузки/задачи, 0030–0039 программы, 0040–0049 Garmin/пуши, 0050–0059 питание/профиль/тренер, 0060–0069
   соревнования/зал/админ. Миграции идемпотентны (`IF NOT EXISTS`, проверка колонок).
5. **Идентичность.** Пользователь = `user_id` (INTEGER). Для существующих `user_id == tg_id`. Новым пользователям без
   Telegram выдаётся id от `WEB_ID_BASE = 5_000_000_000_000_000` (выше любого Telegram id, безопасно для JS). Колонки
   `tg_id` в БД не переименовываем; в новом коде переменная называется `uid`.
6. **Новые сущности** (программы, подходы, задачи, загрузки…): id — строка UUID, генерирует клиент или сервер,
   запись идемпотентна (`PUT /…/{id}`), у строк `updated_at` (ISO UTC, `…Z`) и `deleted_at` (мягкое удаление).
   Это заделка под офлайн (часть 2).
7. **Авторизация.** `src/tjapp/deps.py`: `require_user` (cookie `fepra_session` **или** заголовок `X-Init-Data` для
   старого Mini App), `require_pro`, `require_admin`, `resolve_effective_user` (`?as=` только админ). Все новые
   эндпоинты — через них. Старые эндпоинты Mini App продолжают работать без изменений.
8. **Долгие операции** (LLM, vision, синк Garmin) — задачи: `POST` возвращает `{job_id}`, результат `GET /api/jobs/{id}`
   → `{status: pending|running|done|error, result, error}`. Сервис задач `tj/services/jobs.py` заводит Волна 1.
   Uvicorn работает **одним воркером**: состояние в памяти процесса допустимо (MFA-сессии Garmin, лок Claude).
9. **Ошибки** — JSON `{detail}`, коды 400/401/403/404/409/422. Квоты ИИ (`access.llm_quota_consume`) сохраняются.
10. **Время.** Даты и tz пользователя: `users.tz` нет, берём из `config.toml [user].timezone` через существующий
    код; новые сервисы принимают `today` параметром, чтобы тесты были детерминированными.
11. **Тесты обязательны** на сервисы и роуты (TestClient, tmp-БД, dependency_overrides). Без тестов задача не считается
    сделанной. Не удаляй и не ослабляй существующие тесты; падение чужого теста — сообщи в отчёте.
12. **Документация.** Что сделано и как пользоваться — раздел в `docs/pwa/<область>.md` (кратко: эндпоинты, таблицы,
    решения, что осталось).

## Фронт
`web/` (Vite + TypeScript + React), сборка кладёт статику в `src/tjapp/static/app/`, отдаётся по `/app/`. Клиент
общается только с `/api/*` по cookie-сессии, same-origin.
