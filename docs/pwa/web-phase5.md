# PWA-фронт, фаза 5: ввод и управление

Экраны поверх эндпоинтов из `phase5a.md` и `phase5b.md`. Код в новых каталогах `web/src/screens/{onboarding,settings,meals,comps,coach,club,admin,more}`,
типы и вызовы API — `web/src/api/{profile,meals,comps,coach,club,admin,rest}.ts`, строки — `web/src/i18n/phase5/{ru,en}/*.json`
(подхватываются `import.meta.glob`, общие словари не правились). Общие правки минимальны: строки маршрутов в `App.tsx`, плитки «Ещё» в `Profile.tsx`,
ссылки из Nutrition/Competitions/Профиля, `api/client.ts` (поле `fields` у `ApiError`, тело `FormData`).

## Маршруты
| Маршрут | Экран | Кому |
|---|---|---|
| (перед приложением) | `OnboardingGate`: `GET /api/onboarding`; не хватает полей — мастер по шагам (ник; рост/вес/пол/возраст; зал; цель/город/язык). Ошибка проверки приложение не блокирует | все |
| `/profile/settings` | Настройки профиля: `GET/PATCH /api/profile`, отправляются только изменённые поля, разбор 422 `{detail, fields}`; блок «Часы» по `available_watch_actions` + ссылка на `/profile/garmin` | все |
| `/more` | плитки по ролям (`screens/more/tiles.ts`) | все |
| `/meals`, `/meals/new`, `/meals/:id?day=` | день (итоги, вода ±250/500, список), запись по фото/тексту, правка/перепарс/удаление | Pro/admin, иначе `ProGate` («попроси админа») |
| `/comps`, `/comps/new`, `/comps/:id` | мои и чужие старты; создание с дедупом; страница старта: этапы (текст/фото), результаты (текст/фото), итог, размер поля, вступление | все |
| `/coach` | вопрос -> job -> ответ, последние вопросы, счётчик «осталось N из 3» (админ без лимита) | Pro/admin |
| `/club`, `/club/edit?day=`, `/club/pending`, `/club/stats` | программа дня; редактор с предпросмотром и словарём; очередь черновиков; частота движений и атлеты | просмотр — все; остальное только `roles.admin` или `roles.coach` (+ `can_manage` от сервера) |
| `/admin`, `/admin/users`, `/admin/gyms`, `/admin/stats` | хаб (ссылка на приглашения `/profile/invites`, «Разбор полётов»), роли, залы и тренеры, статистика (Chart.js) | только `roles.admin` (`Guard`) |

Нижняя навигация не менялась (5 иконок), всё остальное — через «Ещё».

## Логика, вынесенная в чистые функции (покрыта тестами)
- `onboarding/validate.ts`: пределы как в `tj/services/profile.py`, `validateField(s)`, `toPatch`, `parseFieldErrors`, `stepsFor`.
- `meals/draft.ts`: редьюсер черновика, накопление `notes` (сервер возвращает обновлённый список, клиент шлёт его вместе с новым `correction`),
  `buildParseRequest`, `buildSaveRequest` (клиентский UUID -> повтор сохранения идемпотентен), пересчёт тоталов при правке блюд.
- `comps/serialize.ts`: разбор «значение, место[, поле]», тела текстового результата и `confirm` (строки без этапа отбрасываются), создание старта, разбор дедупа (`duplicate` -> `candidates`, «присоединиться» или `force_new`).
- `lib/roles.ts`, `admin/logic.ts` (предупреждения: последний админ, админа нельзя лишить доступа/удалить — такие запросы не шлются, сервер всё равно вернёт 409).
- `lib/runJob.ts` (POST -> job -> результат, отмена при размонтировании), `lib/image.ts` (уменьшение фото до 1600 px перед загрузкой, лимит сервера 10 МБ).

## Проверки
`npm run build`, `npx vitest run` (67 тестов, из них фаза 5 — валидаторы и разбор `fields`, черновик еды, сериализация результатов, дедуп, роли/плитки, админ-правила, полные сценарии мастера/записи еды/дедупа/показа управления, проверка что все ключи i18n экранов есть в RU и EN), `npx eslint src`.
Живая проверка в браузере на копии БД (реальные роуты + заготовленные ответы вместо ИИ): запись еды текстом с уточнением и сохранением, вода, правка приёма, старт -> этап -> результат -> итог, админка (пользователи, статистика), настройки профиля, редактор программы (предпросмотр). Фото-цепочки (upload -> parse -> confirm) проверены запросами из браузера к моку, файл через UI не выбирался.

## Что осталось
- Живьём не проверены: мастер онбординга (у dev-пользователя профиль полный, покрыто тестом), фото через системный выбор файла, блок «нераспознанные движения» в редакторе программы (кнопки словаря; API сверен запросом), очередь `pending` (нет черновиков в копии), назначение тренера, «Разбор полётов» (в dev — мок).
- Подключение Samsung/WHOOP/Apple и синк WHOOP — только в боте (в API есть лишь строки действий в `available_watch_actions`).
- Счётчик вопросов тренера считается по `GET /api/coach/recent` за локальные «сегодня» браузера; точный остаток отдал бы отдельный эндпоинт.
- Приём еды из бота с одним `photo_id` не перепарсить (нет файла): показывается ошибка сервера.
- Удаление старта/дивизиона/этапа/результата и переименование залов — нет в API.
- Статика `src/tjapp/static/app/` не пересобиралась в коммитах: собрать на интеграции (`npm run build`).
- Замечание по бэкенду: у общего `get_con`/`open_con` (`tjapp/routes/_common.py`) соединение создавалось в одном потоке пула, а использовалось в другом — редкие 500 «SQLite objects created in a thread». Исправлено `check_same_thread=False` (соединение на запрос, параллельно не используется).
